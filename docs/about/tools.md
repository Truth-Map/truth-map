# Tools we use

These are the structured methods used to keep the research residual-clean and the public surface honest.

## Pattern Inspector (P.I.)

The Pattern Inspector is a structured analytical pass run on high-visibility clusters once a solid base of primary-source material already exists.

**Why we use it**  
Raw collections of documents and claims can grow dense without becoming clearer. The Inspector forces a disciplined second look that answers three practical questions:

1. Where are the densest *documented* edges (people, money, institutions, dates)?
2. How strong is the pattern of those edges?
3. What does the pattern *not* establish?

It is deliberately not a claim-generator. Pattern strength alone never creates a new True claim or moves a Contested label. Its job is to surface concentration, state hard limits, and produce residual recommendations so we know when a module is residual-clean at current public-primary depth.

**How a pass works (current version v0.1)**  
- Start with a defined seed set of already-recorded cards, Claims, and Cases.  
- Extract only documented edges (grants, filings, contemporaneous notes, official records, flight logs, etc.).  
- Group those edges into temporal / personnel / institutional clusters.  
- Rate pattern strength.  
- Explicitly record what the pattern does **not** prove (association ≠ knowledge, participation, or control).  
- Recommend residual actions or declare the seed residual-clean.

As of 2026-08-20, production runs have been completed across ten major clusters (COVID-origins core through QAnon). Public pages surface the method itself and residual status; full Inspector reports stay in the research knowledge base.

This tool exists so density is visible without becoming narrative, and so we stop digging once the public-primary record has been exhausted.

## Five-term evidence labels

Every atomic claim carries one of five explicit labels:

- **True** — strong primary evidence; essentially settled  
- **Likely but Unproven** — good evidence, still incomplete  
- **Contested** — serious evidence-based disagreement remains  
- **Highly Unlikely** — strong evidence against  
- **False** — demonstrably wrong on primary sources  

Evidence is recorded *for* and *against* where it matters. Contested stays Contested until primary documents move it. Association never automatically upgrades a label.

## Layered Assessment Method

Used when public smoking-gun evidence is not expected (deniable influence, intelligence–media relationships, long institutional careers). Claims are kept in four distinct layers instead of being collapsed:

1. **Layer 1 — Documented fact** → labeled **True**  
2. **Layer 2 — Reasonable institutional inference** → **Likely but Unproven**  
3. **Layer 3 — Pattern / continuity hypothesis** → **Contested** (live and testable)  
4. **Layer 4 — Stronger agent / asset claims** → **Highly Unlikely / Unsupported** until primary evidence appears  

Layer 3 is never treated as Layer 1. This keeps later contributors able to attack or support specific layers without rewriting the whole record.

## Narrative Source Residual Process

When a high-impact narrative appears on a Claim or Case, a four-element residual process is applied:

1. **Source** — who first gave the framing high public reach, with primary statements and timestamps.  
2. **Birds on the wire** — who rapidly adopted the same framing in the first 30–90 days (organic amplifiers + any visible coordinated clusters). Flocking is recorded as a signal, not automatic proof of direction.  
3. **Money / Power / Fame** — the visible incentives of the source and major amplifiers.  
4. **Coordination signals** — observable patterns of synchronized or inauthentic amplification. Controller or sponsor identity is elevated only on primary evidence (leaks, platform reports, court documents, declassified material). Otherwise it stays Contested or unclaimed.

Association is never treated as participation, knowledge, or control. The process is Claim/Case-driven only.

## Dating & Evidence Window Standard

This knowledge base is a set of dated snapshots, not a live feed. Continuous re-verification of every card is impossible and would destroy residual discipline. Therefore every new or materially edited card carries two required temporal markers:

- **Last updated** — date of the last material change plus a short note of what changed.  
- **Evidence window / As-of** — the latest date of the primary sources that currently support the labels on the card. This tells the reader: “these conclusions are current only up to this point.”

Bulk backfill of older cards is not required. It happens only when a card is next touched for other reasons. When new primary material appears that could move a label, both fields are updated. This prevents silent staleness while keeping the workload residual-clean.
